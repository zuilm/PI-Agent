# Spawn Pi Agent 阶段结果与后续设计

更新：2026-10-22。本文替换旧版“可选 Pi 规划层 + 固定脚本”方案，与当前二开方向一致；当前实现状态以设计架构和测试报告为准。

## 本阶段已落地

1. Pi 作为实际运行时：工作区 pi.exe RPC 常驻、原生规划/工具调用/记忆/模型回答，不再按提示词执行应用预置任务。
2. 使用 Pi 原生工具工厂及 operations 将 read/write/edit/bash 接入 E2B；不自行实现 Shell、文本编辑器或 Agent Loop。
3. Fastify 负责会话、上传、SSE、取消和文件交付，WebUI 展示真实来源、输出路径、工具参数与结果。
4. publish_artifact 加完成前 output 文件发现，补足原生 Pi 与浏览器下载之间的产品接入；可选独立整数验证器保留为验收支撑。
5. 真实任务不只测示例二，增加统计、去重、CSV、PNG和代码修改；协议回放、真实外部服务和浏览器结果分开统计。
6. 项目配置、扩展、二进制和状态留在工作区，提交文档、测试及历史失败证据同步修正。
7. Pi原生MCP接入wigolo@0.2.1的search/fetch，真实3项联网任务及来源卡片浏览器验收通过；详细配置与限制见web-search.md。

## 后续优先级

| 优先级 | 内容 | 验收依据 |
|---|---|---|
| P1 | 真实取消/超时后继续多轮，验证旧进程事件不串入下一轮；补会话过期和沙箱续期 | 真实 E2B 长命令被终止、文件无延迟修改、同会话下一轮正确 |
| P1 | 对上传文件提示注入、越权路径、伪造成功和敏感信息做真实模型对抗测试 | 保留模型回答、工具参数、沙箱日志及拒绝证据，不以提示词代替隔离 |
| P2 | 扩大已接入Search/Fetch的异常、来源冲突和动态页面验证，按需验收示例一 | 真正搜索/正文，不静默混用年份；失败、冲突与证据局限可解释 |
| P2 | 同一任务多次执行，扩大数据格式和边界样本 | 分模型、提示、次数记录成功率，避免单次10/10当可靠性保证 |
| P3 | ArtifactStore 接 R2/S3，按需加 SQLite | 重启后记录/文件可恢复、签名URL过期有效 |
| P3 | 全新目录/机器安装与分发验证 | 不访问原题目录和个人Pi配置，独立填写凭证后启动 |

联网服务已通过原生MCP接入，不写第二套MCP Client，也不为完成面试题扩展成插件市场或生产平台。普通官方文档与访问拒绝样本已执行；示例一、来源冲突和动态页面仍未执行。

## 时间与取舍

按题目测试约70%的重点，后续先补质量证据，再加功能。保留双面板和内存存储以缩小服务复杂度；现有模型/E2B真实验证已足以评审核心架构。进一步功能需要以明确验收问题驱动，不以增加模块数量作为完成度。
